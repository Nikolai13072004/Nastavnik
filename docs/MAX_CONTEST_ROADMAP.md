# План завершения Наставника

Обновлено 28 сентября 2026 года. Этот план относится к конкурсному пилоту.
Рабочий сценарий существует, но финальная сдача ещё не готова. Текущее
состояние и ограничения перечислены в [статусе](MAX_STATUS.md).

## 1. Воспроизводимый запуск

- [x] Поместить приложение MAX и сервис знаний в одно дерево исходников.
- [x] Собрать оба образа и пройти сквозную проверку на отдельных базах.
- [x] Повторить запуск с пустыми базами: два следующих чистых прогона прошли.
- [ ] Выяснить причину ошибки при обработке документа в первом прогоне и
  проверить запуск без заранее собранных образов.
- [ ] Проверить инструкции на чистой машине без локальных образов и файлов,
  о которых не сказано в [гайде](contest/START.md).
- [ ] Зафиксировать конкурсный commit и его hash после проверки.

## 2. Название и интерфейс

- [x] Установить «Наставник» как публичное название продукта в текущих
  пользовательских экранах и отправить новое имя бота на модерацию MAX.
- [ ] Дождаться модерации, заменить оставшийся старый значок бота и проверить
  карточку в настоящем MAX.
- [ ] Проверить репозиторий, API-документы, презентацию и скрипты на старые
  публичные названия. Технические идентификаторы менять только с миграцией.
- [ ] После действия владельца репозитория обновить GitHub-адреса и ссылки.

## 3. Проверка сценария

- [ ] Пройти путь сотрудника и HR на двух аккаунтах MAX: код, курс, документ,
  вопрос AI, источник, тест, повтор, отчёт и уведомление.
- [ ] Проверить отказ для чужой организации, отозванного документа и истёкшего
  входа. Не использовать реальные данные компании.
- [ ] Проверить качество ответов на нескольких документах и большем наборе
  вопросов; записать правильные ответы, частичные ответы, отказы и ошибки.
  [Текущие измерения](contest/AI_QUALITY_EVIDENCE.md).

## 4. Конкурсный пакет

- [x] Подготовить пошаговый [гайд для проверяющих](contest/JURY_GUIDE.md) и
  учебные данные без секретов.
- [ ] Сверить формат API-пакета с платформой организаторов, если он требуется
  для выбранной номинации.
- [ ] Подготовить короткое видео реального сценария и итоговую PDF-презентацию
  с действующими ссылками и hash версии. Черновики не считать финальной сдачей.
- [ ] Передать тестовые коды и доступ отдельно, не публикуя их в GitHub.

Приоритет сейчас: холодный запуск, актуальные инструкции и один проверяемый
репозиторий. Второй репозиторий для сдачи не нужен; действующие URL и ключи
стенда меняются только после безопасной проверки и резервной копии.
