# Пакет проверки API

Адрес: `https://prodigy-max.45-139-78-17.sslip.io/api/max`.
`openapi.json` описывает основной учебный сценарий и работу HR с документами.
`DATA-API.yaml` содержит проверки по полям задания. Точный машинный формат
платформы организаторов в предоставленном ТЗ не указан, его нужно сверить перед сдачей.
`test-data.json` содержит только вымышленные учебные данные, без паролей и ключей.

[Запуск из исходников](START.md), [план пилота и интервью](PILOT_PLAN.md).
Черновик презентации: `output/pdf/Prodigy-MAX-pilot.pdf`, редактируемая копия:
`output/contest/Prodigy-MAX-pilot.pptx`. Пока нужны реальные снимки MAX,
окончательная версия и действующие профили для проверяющих.

Версия для репетиции: `output/contest/max-source-20260927.zip`, рядом SHA-256.
Внутри оба репозитория и манифест файлов текущей рабочей копии. Это не новый
коммит и не окончательная сдача. Архив исключает базы, кеши, загруженные
оригиналы, закрытые env-файлы и сертификаты. Генератор:
`python scripts/package-max-source.py`; существующий архив не заменяет.

## Доступ

Сотрудник и HR открывают Mini App из своих аккаунтов MAX и вводят личные коды.
Администратор заранее создаёт учебные профили и выдаёт HR нужные права.
HR назначает сотруднику общий курс. Подписанный запуск `/identity` возвращает
`session.token`, который используется как Bearer для MAX API и действует 15 минут.
Обычный браузер, токен бота и ключ Vedomo этот вход не заменяют.

Не публиковать коды, `initData` или токены в Git и общих отчётах.
Для ручной проверки удобнее пройти [гайд MAX](../MAX_DEMO.md).
Рабочие базы и внутренний API Vedomo публично не открываются.

## Порядок проверки

1. Проверить отказ без сессии и отказ неподписанному запуску.
2. Получить курсы, открыть общий курс и подтвердить изучение материала.
3. Начать тест. Получить актуальные `attemptId` и идентификаторы вопросов.
4. Выбрать ответы по текстам из `test-data.json`, сдать тест и повторить тот же
   запрос. История должна содержать одну завершённую попытку, без дубля.
5. Получить ответ AI и открыть документ из его `courseDocumentId`.
   Хеш документа должен совпадать с `documentSha256`.
6. Проверить результат в HR-отчёте. Сотруднику этот маршрут должен отказать.
7. Через HR загрузить новый MD/PDF, проверить черновик, опубликовать и скачать
   оригинал сотрудником назначенного курса. При отзыве или истечении доступа
   скачивание запрещено. Не менять утверждённый источник показа.

Ответ `refused=true` с пустыми источниками означает недостаток подтверждённых
сведений, а не сбой API. Ошибки GigaChat и сети нельзя выдавать за успешную проверку.
При HTTP 429 подождать. Не повторять изменяющий запрос автоматически.

Серверная проверка: `scripts/max-contest-api-smoke.ts --create-temporary-profiles`.
Она проверяет ответы по схемам OpenAPI на своих временных профилях и удаляет
только созданные ей учебные результаты. Настоящие сообщения MAX не отправляет.
Для оригиналов есть отдельная проверка `scripts/max-document-original-smoke.ts`.

Перед конкурсом нужны действующие учебные аккаунты для проверяющих,
телефонная и веб-проверка MAX, фиксация версии и отдельная передача секретов.
