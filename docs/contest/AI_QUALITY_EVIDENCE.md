# Как проверено качество ответов AI

28 сентября 2026 года через рабочий HTTPS MAX выполнена серия из 9 вопросов к
утверждённому учебному документу «Первый день сотрудника в MAX». Использовались
временный назначенный сотрудник, Наставник и GigaChat-2-Pro.
После прогона временная учётная запись и её события удалены. Документ зафиксирован
SHA-256 `4ae1eaa63cc6a90372bde88a52d1c94c573c14ef701f7fac262cfc52199acdd2`.

| Проверка | Результат |
| --- | ---: |
| Фактические вопросы с нужным источником | 7/7 |
| Вопросы без ответа в документе, с отказом без источника | 2/2 |
| Автоматическая проверка типа ответа, документа и цитируемого фрагмента | 9/9 |
| Просмотр смысла всех ответов относительно учебного текста | 9/9 без замечаний |

Проверены потерянный и чужой код, отсутствующий курс, результат проверки знаний,
новая и старая редакции, запрет реальных персональных данных, а также вопросы
о зарплате и точном сроке курса, которых в документе нет. Открытие документа
по возвращённому ID проверено через API; его содержимое совпало с опубликованным.
Медиана времени девяти последовательных ответов - 1,18 с, p95 - 2,28 с.
Эти времена относятся только к данному короткому документу и нагрузку не измеряют.

| Случай | Что проверено при чтении ответа |
| --- | --- |
| Потерянный код | Обратиться к HR за новым кодом |
| Передача кода | Запрет пересылать код другому человеку |
| Нет курса | Обновить назначения, затем сообщить HR |
| Результат теста | Его видит руководитель |
| Новый документ | HR проверяет и публикует редакцию |
| Старая редакция | Не используется для новых ответов |
| Персональные данные | Реальные данные и пароли запрещены в учебном курсе |
| Зарплата, срок курса | Два отказа без выдуманного значения и без источника |

Сценарии и проверки находятся в
[`scripts/max-ai-eval.ts`](../../scripts/max-ai-eval.ts) и
[`scripts/max-ai-eval-core.ts`](../../scripts/max-ai-eval-core.ts).
Машинный отчёт с полными ответами оставлен в закрытом
`output/contest/max-ai-eval-20260928.json`; его не следует смешивать с
обезличенной статистикой HR. Автоматическая проверка ключевых слов - только
фильтр. Оценка смысла выше сделана по девяти прочитанным ответам на простой
учебный текст, не независимым экспертом компании.

Повторный запуск: в одноразовом контейнере приложения с закрытыми настройками
пилота выполнить `node node_modules/tsx/dist/cli.mjs scripts/max-ai-eval.ts
--verify-pilot`. В образ нужно включить два файла скрипта. Для места отчёта
задать `MAX_AI_EVAL_REPORT`; без него файл будет записан в `output/contest/`.
Скрипт откажется работать на иной редакции документа или вне пилотной
организации, а временного сотрудника удалит после проверки.

## Что нужно для проверки на материалах компании

1. Компания утверждает корпус и эталоны до запуска. Для каждого документа
   сохраняются редакция, хеш и ответственный эксперт. Персональные данные
   и закрытые документы не включают в открытый отчёт.
2. Отложенный набор содержит прямые факты, похожие документы, ограничения,
   устаревшие редакции, вопросы без ответа и запрет доступа к чужому курсу.
3. Эксперт проверяет смысл ответа и точный фрагмент источника, отдельно отмечает
   верный, частичный, неверный ответ и корректный отказ. Расхождения разбирают,
   а не исправляют эталон после просмотра результата без следа.
4. Считают доли по каждой категории и число критических ошибок, показывают
   размер выборки, время ответа и повторяемость. После изменения документов,
   поиска или модели прогоняют тот же набор снова и добавляют новые случаи.

Этот пилот **не доказывает качество на большом чужом корпусе**. Сейчас один
AI-запрос принимает не больше 40 разрешённых документов, а один загружаемый
текст ограничен 32 КБ. Перед обещанием работы с сотнями файлов нужно снять
это ограничение безопасным способом и проверить поиск, источники, права,
задержку и стоимость на согласованном многодокументном наборе.

Для проверки на официальных материалах подготовлен
[набор из 30 вопросов](../../services/knowledge/evals/OFFICIAL_ONBOARDING.md)
к текстам Минтруда о трудоустройстве и наставничестве. Поиск по
всем трём файлам нашёл нужные фрагменты для 24 из 24 вопросов с ответом.
[Отчёт по каждому вопросу](../../services/knowledge/evals/results/official-onboarding-all-files-retrieval.json)
сохранён отдельно. Шесть вопросов без ответа эта проверка поиска пропустила.

29 сентября тот же набор проверили на работающем сервисе с GigaChat-2-Pro:
30 вопросов по 4 раза, поиск по всем трём документам. Строгая автоматическая
проверка отметила 26 из 30 вопросов как пройденные во всех попытках; 6 из 6
вопросов без ответа получили отказ. [Полные ответы и времена](../../services/knowledge/evals/results/official-onboarding-gigachat-4x.json)
сохранены в отчёте. [Разбор четырёх непройденных вопросов](../../services/knowledge/evals/results/official-onboarding-review.md)
отделяет две реальные ошибки от двух правильных по смыслу ответов, не прошедших
дословную проверку. Первоначальный одиночный запуск показал 25 из 30 из-за ещё
одной такой формулировки. Оценку не утверждал независимый предметный эксперт.
Нагрузку и качество на большом архиве не проверяли.
