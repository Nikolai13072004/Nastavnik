# Локальная работа с Наставником

Для полной проверки приложения и сервиса знаний из одного репозитория
используйте [запуск из исходников](contest/START.md). Он создаёт отдельные
контейнеры и базы, не трогая рабочий VPS. Проверка не отправляет сообщения
в настоящий MAX и не вызывает GigaChat.

## Модель поиска

Локальный запуск использует подготовленный кеш `BAAI/bge-m3` в томе
`vedomo-max-local-models`. Это старое техническое имя тома, не название
продукта. Если кеша нет, модель нужно скачать до запуска; размер файлов
около 2,3 ГБ. Не удаляйте существующий том, если хотите повторять проверки
без новой загрузки. Скрипт `deploy/max/run-joint-review.py` поддерживает
`--download-model` для отдельного проверочного запуска, но его сценарий с
GigaChat после объединения репозиториев ещё не перепроверен. Для этого нужны
ключ и доверенный сертификат вне Git; проверку TLS не отключать.

## Разработка интерфейса

Нужны локальный `.env` и отдельная dev-база. Установите зависимости только
если их нет или изменился lockfile:

```powershell
npm ci
docker compose -f compose.max-dev.yml up -d --wait
npx prisma migrate deploy
npm run dev:safe
```

На Windows используйте `npm run dev:safe`, а не прямой `next build` или
Turbopack. Адрес приложения - `http://localhost:3101/max`, проверка
процесса - `http://localhost:3101/api/health`. Локальный браузер не заменяет
подписанный вход из MAX. Для остановки БД без удаления данных:

```powershell
docker compose -f compose.max-dev.yml stop
```

Не запускайте `prisma/seed.ts` на существующей базе: скрипт удаляет данные и
создаёт простые демонстрационные пароли. Не используйте `down -v` на рабочем
стенде. Токен бота и ключ GigaChat храните только в закрытом окружении.

## Проверки кода

`npm run test:unit`, `npm run lint`, `npx tsc --noEmit --incremental false`.
Публичный путь сотрудника и HR описан в [гайде](MAX_DEMO.md).
