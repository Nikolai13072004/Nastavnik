# Пилотный стенд Prodigy MAX

Адрес: `https://prodigy-max.45-139-78-17.sslip.io/max`. Сервер: `45.139.78.17`, папка `/opt/prodigy-max`, Compose project `prodigy-max-pilot`. Это технический пилот на общем сервере, не полный релиз LMS. Домен использует sslip.io и не требует покупки.

## Границы стенда

- У пилота собственные web, PostgreSQL, gateway, worker, сеть и volume. Остальные проекты и настройки общего proxy не менять.
- Публично открыты только Mini App и нужные ему MAX API. Обычные страницы LMS и административные маршруты закрыты gateway.
- Web ограничен 768 MiB и 0.7 CPU, БД - 384 MiB и 0.35 CPU. Для защищённых запросов к Vedomo web также подключён к egress-сети. Эти лимиты не заменяют наблюдение за общим сервером.
- В web установлено `MAX_DISABLE_EMAIL=true`. Worker работает отдельно; изменение его окружения требует отдельного обновления контейнера.

## Обновление

Собирать образ локально, не на общем VPS. Тег обновления: `prodigy-max:chat-20260926`, overlay `compose.chat.yml`. Перед загрузкой нового образа проверьте свободное место, состояние своих контейнеров и создайте резервную копию только пилотной БД. Файл `.env` и токены не помещать в образ или логи. После передачи образа сверить SHA-256 архива.

На сервере сначала проверить новый Compose через `docker compose config --quiet`, затем применить миграции и обновить только нужные сервисы. Не выполнять глобальные Docker prune, restart или `down -v`. На последнем обновлении пересозданы web и worker пилота. БД, gateway и соседние проекты не перезапускались.

Gateway разрешает имя `web` через Docker DNS с обновлением каждые 5 секунд.
После изменения `nginx.conf` проверить его командой `nginx -t` в одноразовом
gateway-контейнере, сохранить старый файл и выполнить `nginx -s reload` только
в `prodigy-max-pilot-gateway-1`. Общий proxy не менять. Копия прежнего файла:
`backups/nginx-before-dns-20260926.conf`.

Для проверки:

```sh
cd /opt/prodigy-max
docker compose -f compose.yml -f compose.chat.yml config --quiet
docker compose -f compose.yml -f compose.chat.yml ps
docker compose -f compose.yml -f compose.chat.yml logs --tail 30 web gateway
```

Проверить HTTPS без отключения TLS: `/max` возвращает 200, `/login` и `/admin` - 404, MAX API без сессии - 401. Не проводить нагрузочный тест на общем сервере.

Для временного закрытия сайта: `docker compose stop gateway` из `/opt/prodigy-max`. Перед обновлением сохранять прежний Compose и образ. Последняя копия - `compose.yml.before-notices`, прежний образ `prodigy-max:pilot-20260924-revisions`, дамп БД `backups/pre-notices-20260924.dump`. Миграция `20260924000600` добавила тип сообщения и идентификатор редакции в очередь бота. При обновлении worker останавливался до применения миграции; обновлены только web и worker. Общие сервисы не перезапускались.

Перед обновлением 26 сентября сохранены `backups/pre-ux-20260926.dump` и
`backups/compose-before-ux-20260926.yml`. Схема БД не менялась. Для отката web и worker
используйте исходный `compose.yml` без нового overlay: `up -d --no-deps --no-build web worker`.
Для обычного обновления обязательно добавляйте `compose.chat.yml`, иначе выберется старый образ.

Подписка MAX должна получать `bot_started` и `message_created`. Скрипт
`scripts/max-chat-subscription.mjs` сначала проверяет существующую подписку;
режим `--apply` добавляет только `message_created`, сохраняя прежние события и URL.
Запускайте его отдельным одноразовым контейнером worker с тем же env и сертификатом,
а не вторым Node-процессом внутри ограниченного работающего worker. Скрипт можно
смонтировать из текущей конкурсной ветки только для чтения.

Проверка `scripts/max-chat-smoke.ts --send-pilot-help` отправляет одно настоящее
сообщение помощи привязанному пилотному аккаунту через очередь. Она использует
синтетический входящий запрос, не заменяет сообщение пользователя с телефона.

Документы .txt и .md до 32 КБ и PDF до 512 КБ, 10 страниц принимаются как черновики. Из PDF сохраняется только извлечённый текст до 32 КБ. Скан без текста не принимается. Оригиналы не попадают в `/uploads` и не отправляются в Vedomo. Перед показом проверяются текущая привязка MAX, организация и активное назначение курса. Для реальных конфиденциальных документов пилот пока не использовать. AI включён только для утверждённого учебного документа демо-курса. Ключ Vedomo хранится в закрытом `.env` и требует ротации до истечения 30 дней с выдачи 24 сентября 2026 года.

## До полного релиза

Нужны проверка HR-экрана с отдельного MAX-аккаунта, разбор оставшихся предупреждений `npm audit`, проверка восстановления из резервной копии и полный тест AI на телефоне. Настоящие документы сотрудников пока не подключать. При зависшей отправке бота не возвращать очередь в `PENDING` без проверки доставки: возможны дубли сообщений.

Корневой сертификат MAX монтируется только в worker через `max-ca.pem`. Не устанавливать его на весь сервер и не отключать проверку TLS. Источник: `https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt`; отпечаток нужно сверять при обновлении сертификата.
