# Проверка ответов по материалам о трудоустройстве и наставничестве

Набор содержит 30 вопросов к трём небольшим фрагментам открытых материалов
Минтруда России: 24 вопроса с ответом в тексте и 6 вопросов, для которых
ответа нет. Это проверка работы с конкретными редакциями документов, а не
правовая консультация и не оценка на документах произвольной компании.

| Материал | Оригинал |
| --- | --- |
| Рекомендации по организации наставничества в сфере труда, утверждены 22.04.2026 | [Минтруд](https://mintrud.gov.ru/ministry/programms/trudotn/nastav) |
| Заключение трудового договора, страница изменена 07.03.2025 | [Минтруд](https://mintrud.gov.ru/ministry/programms/trudotn/dogovor) |

Оригинальные файлы сохранены в `evals/sources/official-onboarding/`. Извлечения
лежат в `evals/datasets/materials/official-onboarding/`; их размер не превышает
32 КБ на файл. Скрипт `evals/prepare_official_onboarding.py` сверяет SHA-256
оригиналов и воспроизводит извлечения без ручной правки текста. Материалы сайта
Минтруда опубликованы по лицензии CC BY 3.0; указание источника сохранено в
каждом извлечении.

## Проверка поиска 29.09.2026

В локальном прогоне поиск по всем трём файлам нашёл ожидаемый фрагмент для
каждого из 24 вопросов с ответом в документах. Четыре критических случая тоже
прошли. [Машинный отчёт](results/official-onboarding-all-files-retrieval.json)
содержит результат каждого вопроса. Шесть вопросов без ответа в режиме проверки
поиска пропущены. GigaChat не вызывался, поэтому правильность ответов и отказов
этот результат не измеряет. Поиск на трёх небольших файлах не доказывает работу
на большом архиве компании.

Повторить этот замер можно командой:

```bash
python -m evals.run_eval --dataset evals/datasets/official-onboarding.json --retrieval-only --all-files --out evals/reports
```

## Ответы GigaChat 29.09.2026

На работающем сервисе знаний проверили все 30 вопросов с поиском по всем трём
файлам. Модель - GigaChat-2-Pro. Каждый вопрос задали четыре раза, всего 120
ответов. Тест использовал отдельное временное пространство и не менял курсы MAX.

Строгая автоматическая проверка отметила 26 из 30 вопросов как пройденные во
всех четырёх попытках. Все 6 вопросов без ответа в документах получили отказ
во всех попытках. Медиана времени поиска и ответа внутри сервиса - 1,18 с,
95-й процентиль - 2,28 с. Эти времена не включают MAX и не измеряют нагрузку.

[Машинный отчёт](results/official-onboarding-gigachat-4x.json) содержит
вопросы, все ответы, краткий просмотр найденных фрагментов и время каждой
попытки. В ответах видны две реальные ошибки: сервис не нашёл ответ о выборе
наставника для конкретного работника и отказался отвечать о документах воинского учёта,
хотя ответ есть в материале. Ещё два ответа по смыслу верны, но не содержат
заданную проверкой дословную фразу. [Разбор](results/official-onboarding-review.md)
показывает эти случаи отдельно. Первоначальный одиночный прогон дал 25 из 30:
ответ рабочей группы тогда тоже не прошёл из-за формы слова. Это ограничение
проверки по ключевым словам, а не основание скрывать первый результат.

Результат пока не проверен независимым предметным экспертом. Три небольших
документа не доказывают качество на большом архиве компании.

## Запуск

В окружении с зависимостями проекта:

```bash
python -m evals.prepare_official_onboarding --check
python -m pytest tests/test_official_onboarding_dataset.py -q
python -m evals.run_eval --dataset evals/datasets/official-onboarding.json --all-files --repeat 4 --out evals/reports
```

Последняя команда требует настроенных поиска и модели. Она создаёт отдельное
тестовое пространство, загружает только указанные три файла и сохраняет ответы
с автоматической проверкой. Запускать её нужно отдельно от рабочего MAX-курса.
Если используете существующее тестовое пространство, укажите `--workspace-id`
и `--no-ingest` только после сверки загруженных файлов.

Автоматическая проверка ищет ожидаемые слова и фрагменты. Она не доказывает
смысловую правильность. Перед публикацией процента успешных ответов человек
должен прочитать все 30 ответов, проверить источник каждого ответа и отдельно
отметить верные, частичные, неверные ответы и корректные отказы. В итоговом
отчёте нужны числитель, знаменатель, ошибки и версия модели.

Ранее опубликованные результаты на другом, учебном документе к этому набору
не относятся.
